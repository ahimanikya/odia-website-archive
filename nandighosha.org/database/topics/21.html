This is my experience on Software lifecycle. The known theory is software life cycle has several phases like Analysis, Design, Implementation and Testing and Maintenance. Can you guess how many developers aware of one more phase &quot;Refactoring the code base and design&#8221; or how many really care about this? There are very few. Let me give a brief note of what I am talking about. Refactor is a phase usually comes after implementation. After the code has been written and is functionally working, then refactoring techniques are needed because we need to keep the code and design clean. I often hear from managers that this is not always top priority; we just need to make it work. I would strongly suggest the &#8220;two step process&#8221; of Add Functionality, then Refactor Design, gives the twin benefits of faster development and maintainable code. So whenever you add functionality or update the existing functionality, refactor your code and design. I will write some more articles on what is refactoring in OO Java world. Asha Balasubramanyan http://www.ammu.org
